# CampusSwap

A campus marketplace for students: list textbooks, electronics, dorm gear and
supplies for sale, swap, or free — then chat with the other student to arrange
the handoff.

Built with Flutter + Firebase (Auth, Cloud Firestore, Storage, Cloud Messaging).

## Features

- **Email/password auth** with a campus verification gate (`@university` email).
- **Browse & search** listings with category / type filters, sorting, and a
  keyword index maintained on every write.
- **Create listing** with up to 6 photos uploaded to Firebase Storage, plus
  course code / ISBN fields for textbooks. Listing owners can edit, mark
  reserved/sold/swapped, or delete.
- **Favorites** stored per-user in a `users/{uid}/favorites` subcollection.
- **Chat** — one conversation per buyer/listing pair, with photo messages,
  per-user unread counts, `Seen` receipts, and auto-scroll.
- **Swap proposals** — offer one of your own active listings (plus a note) on a
  swap-type listing; owners accept/decline and proposers can cancel, all from
  the Swaps tab. Accepting flips the listing to `swapped` in one transaction.
- **In-app notifications** — a `notifications/{uid}/items` feed for new
  messages and swap activity, with unread badges and mark-as-read.
- **Reports** — flag a listing with a reason and optional details.
- **Profiles** — editable name, university, bio and photo; profile shows rating,
  review count and listing count.
- **Push notifications** — FCM tokens saved to the user profile and refreshed
  on rotation (server-side delivery needs a Cloud Function — see below).
- **Kenyan shilling** pricing (`KSh 1,500`) via a single currency formatter.
- **Dark mode**, persisted across sessions.

> **No Cloud Function yet.** In-app notifications are written client-side by the
> repository when an action happens (a message sent, a swap proposed/answered).
> Security rules let any verified student create a notification in another
> user's feed but only the owner may read, mark read, or delete it. Delivering
> those as real push notifications requires a backend FCM sender (out of scope).

## Tech stack

| Concern | Choice |
| --- | --- |
| UI | Flutter (Material 3), `go_router` for navigation |

## Project structure

```
lib/
  main.dart                     # Firebase bootstrap + ProviderScope
  firebase_options.dart         # Generated by the FlutterFire CLI
  src/
    app.dart                    # MaterialApp + GoRouter route table
    providers.dart              # Riverpod providers (auth, data, prefs)
    core/app_theme.dart         # Light/dark ColorSchemes and theme
    models/models.dart          # Freezed data models + enums
    data/                       # Repositories (auth, firestore, storage, FCM)
    screens/                    # One file per screen
    widgets/app_widgets.dart    # Shared cards, states, formatters
firestore.rules                 # Firestore security rules
storage.rules                   # Cloud Storage security rules
firestore.indexes.json          # Composite indexes
test/                           # Unit + widget tests
```

## Firestore data model

| Path | Purpose |
| --- | --- |
| `users/{uid}` | Profile, campus, bio, photo, FCM tokens |
| `users/{uid}/favorites/{listingId}` | Saved listings |
| `listings/{listingId}` | Listing document incl. `searchKeywords` + `viewCount` |
| `conversations/{id}` | Chat thread metadata (participants, last message) |
| `conversations/{id}/messages/{messageId}` | Individual messages + read receipts |
| `swaps/{id}` | Trade offers between two students |
| `notifications/{uid}/items/{id}` | Per-user in-app notification feed |
| `reports/{id}` | Listing reports (write-only for clients) |

## Setup

### Prerequisites

- Flutter 3.35+ (Dart 3.9+) and the `flutterfire_cli`
- A Firebase project with **Auth (Email/Password)**, **Firestore**,
  **Storage**, and **Cloud Messaging** enabled

### 1. Install dependencies

```bash
flutter pub get
```

### 2. Connect Firebase

This repo is already wired to a project (`campusswap-2c21f`) via
`firebase.json`, `.firebaserc`, and `lib/firebase_options.dart`. To use your
own project instead:

```bash
flutterfire configure \
  --project=<your-project-id> \
  --platforms=android,ios \
  --android-package-name=edu.campusswap.campus_swap \
  --ios-bundle-id=edu.campusswap.campusSwap
```

Then update `firebase.json`, `.firebaserc`, and the Android
`applicationId` / iOS bundle identifier if your package names differ.

### 3. Deploy security rules and indexes

```bash
firebase deploy --only firestore:rules,firestore:indexes,storage
```

### 4. Run

```bash
flutter run
```

### 5. Release builds (Android)

The release build type falls back to the debug key so `flutter run --release`
works out of the box. To sign releases properly:

```bash
keytool -genkey -v -keystore ~/upload-keystore.jks \
  -keyalg RSA -keysize 2048 -validity 10000 -alias upload
cp android/key.properties.example android/key.properties
# then edit android/key.properties with your keystore paths and passwords
flutter build apk --release --split-per-abi
```

iOS note: `ios/Runner/GoogleService-Info.plist` is not committed to this repo
(it can only be generated from the Firebase console / an Xcode machine). Run
`flutterfire configure` on a macOS host or download the plist from the
Firebase console before an iOS build.

```bash
export CAMPUSSWAP_FIREBASE_API_KEY="<web-api-key>"
export CAMPUSSWAP_DEMO_PASSWORD="<demo-password>"
```

Optional overrides:

```bash
export CAMPUSSWAP_FIREBASE_PROJECT_ID="<firebase-project-id>" # default: campusswap-2c21f
export CAMPUSSWAP_DEMO_SIGNIN_EMAIL="<demo-user-email>"       # probe scripts only
```

## Security rules highlights

- Only verified students can read listings; only owners can edit or delete
  them, and `sellerId` / `createdAt` are immutable once written.
- Listing owners may change status and content; any signed-in student may
  increment `viewCount` by exactly one per write.
- Favorites live under the owning user and are private; the listing's
  `favoriteCount` may only be moved by exactly ±1 per write.
- Chat is restricted to the two participants of a conversation.
- Swap proposals can only be accepted/declined by the listing owner, or
  cancelled by the proposer, and only while still pending.
- Users cannot self-assign `role`, `rating`, or `ratingCount`.
- Reports are write-only to clients — reading them requires the console or
  privileged tooling.
- Storage: listing, profile, and chat images each live under owner/scope-based
  paths, capped at 5 MB and restricted to `image/*` content types.
